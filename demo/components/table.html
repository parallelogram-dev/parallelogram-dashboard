Editable rows with folding actions

In a .table--editable, cells hold .table__control inputs and selects that sit flush until hovered or focused (--number right-aligns figures). Mark rows with unsaved edits .table__row--changed and added rows .table__row--new. Give the actions cell data-overflow-actions and mark foldable buttons data-priority="low" (folds first) or "medium". Rows in the same .table__wrapper fold together, before the table would scroll sideways or a text input could no longer show its value; anything marked data-overflow-protect counts too. The script only sets data-overflow-level on the wrapper and the stylesheet hides what that level folds. The "⋯" menu is built when it opens, from each action's icon and aria-label or data-label, and floats in the top layer so the table can't clip it. Give longer values such as SKUs .table__control--wide so the table scrolls rather than squeezing them, and add .table--sticky-actions to keep the actions column pinned while it scrolls, with a shadow while columns sit underneath. While any row's checkbox is ticked, row actions are hidden (keeping their space) so the bulk actions take over. This example is narrow, so its actions fold.

Set data-row-state="saving", "saved" or "error" on a row to show a spinner, a tick or a warning in its .table__checkbox cell while the row saves itself. In any .table--editable, the keyboard moves like a spreadsheet: arrow keys move between cells (left and right once a value is fully selected or the caret reaches its edge), Enter and Shift+Enter move down and up, Escape restores the value the cell had when it was focused, and Ctrl or Cmd+D copies the value from the cell above.

Give the table data-table-paste and pasting a block copied from a spreadsheet into one of its cells opens a dialog rather than filling one field. It previews the block with a column picker above each pasted column (matched by heading when the first row looks like headings, otherwise by position across the visible columns), and asks whether to update rows from the one pasted into or add new rows; lines past the last row can become new rows too. Values a select has no option for, or text in a number column, are struck through and skipped. Point the attribute at a row <template> (data-table-paste="#rowTemplate") to allow adding rows. Applying fires input and change on each control, then table:paste with { updated, added, undo } for an Undo toast. Try copying a few cells from a spreadsheet into this example.

Full-screen editing

Give a card data-expandable and a button inside it data-expand, and the button moves the card into a full-screen <dialog class="expandable"> and back (Escape also returns it). The card keeps its place on the page, carries data-expanded while it is full screen and dispatches expandable:change. Swap the button's label with data-expand-label and data-collapse-label, and give it both a data-expand-icon="expand" and a "collapse" icon. Columns marked data-column-expanded show only while expanded. In a full-screen card, .table--sticky-header keeps the header row in view and .table--sticky-start pins the first column (and the checkbox column before it), with a shadow once columns scroll underneath.

A column picker is a dropdown menu with data-table-columns="#tableId" whose items carry data-column-toggle="key"; each hides or shows every cell marked data-column="key", the choice is remembered per table, and the spreadsheet keys skip hidden columns. It fits in a footer row under the actions column, beside an add-row button; give that row's first cell data-column-span and it spans whatever columns are showing.

Give the table data-table-sort and its .table__head--sortable headers sort the view by clicking or Enter: ascending, descending, then back to the natural order. Use a sort icon with data-sort="ascending" and "descending" paths and the one not in use fades; put it first with .table__sort-icon--start in right-aligned columns. Cells sort by their control's value, a data-sort-value or their text, numbers as numbers and blanks last. The table carries data-sorted while sorted. Sorting never changes the saved order: rows added, duplicated or put back while sorted keep their natural place, and edited values don't move rows until the next sort.

Reordering rows

Give a table data-table-reorder and a first .table__handle column holding a handle button in each row. Drag a handle and the row moves into place as you go, with the other rows sliding aside and the table scrolling near its edges; Escape puts it back. With the keyboard, focus a handle and press Space to pick the row up, the arrow keys to move it and Space to drop it. The row being moved carries data-dragging, moves are announced, and the table fires table:reorder with { row, from, to }. A reorderable table can't also sort by column, so leave its headers plain. With .table--sticky-start, the handle, checkbox and first column stay pinned together.
